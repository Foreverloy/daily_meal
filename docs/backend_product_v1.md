## 1. 文档边界与审查

本文维护 Go 后端的交付范围和接口验收。[总产品文档 V1](product_v1.md)是前后端共同读取的唯一业务规则来源，维护产品定位、整体阶段、核心使用流程及业务规则；本文不复制共同规则。

## 2. 交付范围

V1 交付可独立使用的 Go HTTP API，不依赖网页或 Agent，包含：

1. 默认营养目标与指定日期的目标设置。
2. 食物创建、查询、修改及营养数据维护。
3. 固定菜品配方管理和营养计算。
4. 早、中、晚餐的混合饮食记录，支持补记、修改和删除。
5. 每餐、全天营养汇总及目标对比。

后端 V1 按个人使用设计，不引入多用户体系。Python 服务、截图识别、对话、菜单推荐和任务队列属于后续阶段。

## 3. 业务规则与后端职责

业务规则直接读取总产品文档，不在此另行定义：

| 模块 | 共同规则位置 | 后端职责 |
| --- | --- | --- |
| 每日目标 | 总产品文档第 5.1 节 | 校验目标、推导克数、保留历史、解析日期覆盖 |
| 食物库 | 总产品文档第 5.2 节 | 保存与查询食物营养，校验单位及同类换算 |
| 菜品库 | 总产品文档第 5.3 节 | 保存完整配方、校验食材、计算整道营养 |
| 饮食记录 | 总产品文档第 5.4 节 | 保存历史快照，处理补记、修改与删除 |
| 汇总与目标对比 | 总产品文档第 5.5 节 | 汇总每餐与全天摄入，保留未知及完整性，计算目标差距 |

数据库结构、HTTP 路径、字段和错误格式由[后端实现文档](implementation_v1.md)与[OpenAPI](../backend/openapi/openapi.json)说明。

## 4. 接口验收

- 通过接口独立跑通总产品文档第 4 节的完整使用流程。
- 通过接口验证总产品文档第 8 节全部业务场景，覆盖目标计算与历史、单位换算、整道菜品、配方失败、历史快照、未知与零及记录纠正。
- 后端输出营养结果、目标来源和数据完整性，供调用方使用；接口验收不以网页启动或页面布局为前置条件。
- 验收要求不代表已经执行或通过验证。具体测试方式见[后端 README](../README.md#验证)。
