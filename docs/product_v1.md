## 2. 产品定位与使用者

Daily Meal 是面向个人健身餐场景的饮食管理工具，参考“薄荷健康”的相关功能和操作流程，帮助使用者维护常吃食物与菜品、记录每日三餐，并查看营养摄入和目标差距。

项目同时用于学习 Go 后端与后续 Agent 应用开发。V1 按单人使用设计，不引入多用户体系；围绕已确认的饮食管理需求保持简单。

## 3. 交付范围与阶段

| 阶段 | 用户可获得的能力 | 范围边界 |
| --- | --- | --- |
| 后端 V1 | 通过接口设置目标、维护食物与菜品、记录三餐、查询营养汇总 | 可独立完成核心流程，不依赖前端或 Agent |
| 网页 V1 | 在电脑和手机浏览器完成相同业务流程 | 今日饮食、食物库、菜品库、目标设置四个模块 |
| 后续 Agent | 通过截图维护食物，通过对话记录饮食、调整目标、录入菜品和推荐菜单 | 后续阶段，不属于 V1 验收范围 |
| 后续 iOS | 将网页能力延伸到 iOS App | 后续阶段，需另行完成平台适配与验证 |

V1 不包含多用户与登录体系、截图识别、聊天、菜单推荐和原生 App 交付。不支持“个、份、碗”等食物计量单位、重量与体积互转、菜品分份、成品称重和剩余量管理；不设置每餐独立目标或钠、维生素等额外营养目标。

## 4. 核心使用流程

1. 设置默认每日热量与蛋白质、碳水、脂肪供能占比；需要时单独调整某一天。
2. 录入常吃食物及每 100g 或每 100ml 的营养数据，按名称搜索和维护。
3. 从食物库选择食材和用量，保存固定菜品，查看整道菜营养。
4. 选择日期和早餐、午餐或晚餐，逐条添加食物或整道菜品。
5. 查看每餐及全天营养、每日目标和剩余额度。
6. 补记、修改或删除饮食记录，并查看更新后的汇总。

尚未设置目标时，仍可记录和查看饮食；页面引导设置目标，但不展示无法计算的剩余额度。

## 5. 功能与业务规则

### 5.1 每日营养目标

- 输入每日热量（大卡 / kcal）及蛋白质、碳水、脂肪的供能百分比。热量必须大于 0，各占比在 0～100% 之间，合计为 100%。
- 三大营养素的克数目标由热量和占比推导，不另设一套独立克数目标：

| 指标 | 克数目标计算 |
| --- | --- |
| 蛋白质 | 每日大卡 × 蛋白质占比 ÷ 100 ÷ 4 |
| 碳水 | 每日大卡 × 碳水占比 ÷ 100 ÷ 4 |
| 脂肪 | 每日大卡 × 脂肪占比 ÷ 100 ÷ 9 |

- 默认目标每天沿用，修改从当天生效，保留更早日期适用的目标。
- 指定日期可以设置独立的完整覆盖目标，其优先级高于默认目标；修改默认目标不覆盖已设置的日期目标。
- 删除日期覆盖后，恢复该日期适用的默认目标；如该日原本没有默认目标，则恢复为未设置。
- 首次设置默认目标之前的日期不会套用之后的设置，可单独补设该日目标。
- 显示目标来源：默认、该日覆盖或未设置。操作上明确区分“从今天修改默认目标”和“仅修改所选日期”。
- 每餐仅统计摄入；钠、钙、维生素等只记录和汇总，不设置目标。
- 日期格式为 `YYYY-MM-DD`，默认按 `Asia/Shanghai` 时区判断“今天”，各端保持一致。

### 5.2 食物库

- 支持创建、按名称搜索、分页查询、查看详情和修改名称及营养数据。
- 名称应方便辨别，例如“生米”“熟米饭”“某品牌牛奶”；搜索和选择时同时显示计量基准。
- 每种食物创建时选择一种营养基准，创建后固定：

| 营养基准 | 可输入的用量单位 | 换算规则 |
| --- | --- | --- |
| 每 100g | g、kg | 1kg = 1000g |
| 每 100ml | ml、L | 1L = 1000ml |

- 用量必须大于 0，仅允许同类换算。鸡蛋按重量记录，牛奶可按体积记录。
- 热量必填，其他营养数据允许未知；已知数值不得为负。食物热量保留录入值，不强制根据三大营养素反推覆盖。
- V1 营养指标包括热量（kcal）、蛋白质（g）、碳水（g）、脂肪（g）、钠（mg）、钙（mg）、维生素 C（mg）和维生素 D（μg）。更多指标按后续需求扩展。
- 食物用量单位与营养素单位分别展示，例如牛奶用量为 ml，蛋白质为 g，钠为 mg。
- 营养输入留空表示未知，填写 0 表示已知为零；清空可选营养值后恢复为未知。
- 实际摄入营养 = 每 100g/ml 的营养 × 换算后的用量 ÷ 100。

### 5.3 菜品库

- 支持创建、按名称搜索、分页查询、查看详情和修改固定配方。
- 一道菜由名称、至少一种食物及每种食物的用量组成。同一种食材在表单中合并为一行，可调整或移除食材。
- 食材用量遵守对应食物的单位规则，重量和体积食材可存在于同一道菜中，无需将两类用量相加。
- 整道菜营养按全部食材的实际用量计算并求和；缺失营养按第 5.5 节表达，不按零补齐。
- 菜品默认整道吃完，记录时直接计入全部营养，不填写份数、摄入比例或成品重量。
- 查询菜品时，营养反映当前食材数据。修改食物或配方会影响后续菜品查询和新记录，已保存的饮食记录保持不变。
- 配方中存在非法食材或用量时，整道配方保存失败，不留下只保存部分食材的结果。

### 5.4 饮食记录与历史保留

- 按日期及早餐、午餐、晚餐记录；默认使用今天，也可选择其他日期补记。
- 同一天同一餐允许多条记录，每条选择一种食物或一种菜品，两类记录可混合存在。
- 食物需填写用量和允许的单位；菜品只需选择模板，即表示整道吃完。
- 支持查看、修改日期、餐次和记录内容，以及删除记录。
- 保存时保留当时的名称、营养及计算结果；菜品还保留当时食材组成和用量。历史详情展示这些记录时的信息。
- 修改食物或菜品模板不改写历史。仅修改记录日期或餐次，原营养保持不变；修改食物摄入量，按该记录原有营养基准重新计算。
- 更换为其他食物或菜品时，使用新选择内容当时的数据生成记录快照。
- 补记使用录入时所选食物或菜品的数据，不追溯构造食物库在过去日期的状态。
- 保存、修改或删除后立即更新相应日期的汇总；移动到其他日期时，原日期和新日期都要更新。

### 5.5 营养汇总与目标对比

- 分别展示每餐和全天的营养汇总，每个营养指标独立计算完整性。
- 全部受支持指标都应展示，包括没有数据的指标。

| 数据情况 | 展示规则 |
| --- | --- |
| 已知为零 | 显示 0 |
| 有记录，但某指标全部未知 | 显示“未知”，标明数据不完整 |
| 某指标部分已知 | 显示已知部分合计，并标明“数据不完整” |
| 某指标全部已知 | 显示完整合计 |
| 空餐或当天没有记录 | 合计为 0，数据完整 |
| 页面尚未加载或加载失败 | 显示对应状态，不当作摄入为 0 |

- 热量、蛋白质、碳水、脂肪展示每日目标、已摄入和剩余额度；其他营养素只展示摄入和完整性。
- 某项指标有目标且摄入完整时，剩余额度 = 目标 − 摄入。任一条件不满足时，显示“暂无法计算”，不做达标判断。
- 剩余额度为负表示超出目标，页面应表达“超出”，不能截断为零。
- 计算保留中间精度，展示时再格式化，不逐项提前取整。

## 6. 网页页面与交互要求

主导航为“今日”“食物”“菜品”“目标”。手机使用底部导航，电脑使用顶部或侧边导航，复用相同业务流程。

| 页面 | 主要内容与操作 |
| --- | --- |
| 今日饮食 | 切换日期，查看目标与汇总、三餐明细，添加、修改和删除记录 |
| 食物库与详情 / 表单 | 搜索和分页，创建食物，查看和修改名称、每 100g/ml 营养；编辑时基准单位只读 |
| 菜品库与详情 / 表单 | 搜索和分页，维护食材与用量，查看整道菜营养，从详情进入饮食记录 |
| 目标设置 | 设置默认目标、日期覆盖、恢复该日默认目标，展示占比合计和目标来源 |
| 饮食记录表单 | 带入当前日期和餐次，选择食物及用量或整道菜品，保存或修改记录 |

- 手机页面不出现页面级横向溢出，键盘打开后仍可输入和保存；电脑布局清晰，表单与按钮支持触摸和键盘操作。
- 表单字段提供明确标签、营养单位和可定位的错误提示。
- 页面区分加载中、空内容、失败和提交中；失败时保留未保存输入。
- 提交期间阻止重复点击。网络中断导致保存结果不明确时，提示先刷新确认，不自动重复提交。
- 保存成功后展示结果并刷新相关数据；快速切换日期或搜索时，旧结果不得覆盖当前内容。
- 直接打开或刷新页面地址仍能进入对应页面。

## 7. 后续 Agent 与 iOS 边界

以下是后续方向，不计入 V1 完成标准；具体扩展仍须经过产品审查。

- 截图中的食物营养先转换为统一基准，例如将每 250ml 转为每 100ml，再维护食物库。
- 对话可用于记录饮食、调整目标、录入菜品和推荐菜单。食物匹配、用量或单位不明确时，先向用户补问。
- 营养计算和业务校验复用现有业务能力，避免对话结果与普通记录产生不同计算规则。
- 单次配方调整只作用于本次配方；用户明确要求修改模板时才更新模板。记录时保存本次实际配方与营养。
- 推荐与实际摄入分开，推荐菜单不自动计入饮食记录。
- Agent 重试不得生成重复饮食记录；结果不明确时先查询状态。成功操作后，页面刷新相关业务数据。
- iOS 复用网页业务与交互，另行验证设备上的导航、键盘、相册选择和权限等体验。

## 8. V1 产品验收

后端阶段通过接口验收，网页阶段通过电脑和手机浏览器验收。以下为验收要求，不表示本次已执行这些验证。

| 场景 | 预期结果 |
| --- | --- |
| 完整使用流程 | 能完成“设置目标 → 创建食物 → 创建菜品 → 记录三餐 → 查看汇总” |
| 目标计算 | 输入 2000 kcal、蛋白质 30%、碳水 40%、脂肪 30%，得到约 150g、200g、66.67g 的克数目标 |
| 历史与日期目标 | 默认修改从今天生效，更早目标不变；日期覆盖优先，删除后恢复该日适用的默认目标或未设置状态 |
| 没有目标 | 仍可记录和查看摄入，不显示虚假的剩余额度 |
| 食物用量 | 每 100g 为 100 kcal 的食物，摄入 0.25kg 计为 250 kcal；拒绝对该食物使用 ml |
| 菜品与混合记录 | 食材营养正确求和，菜品整道计入，同餐可以继续添加单独食物或饮品 |
| 配方校验 | 非法食材或用量导致整道配方保存失败，无部分保存 |
| 历史快照 | 修改食物或菜品模板不影响旧记录；仅改记录食物用量时仍按原营养基准计算 |
| 未知与零 | 已知零、全部未知、部分已知、空餐分别按规则表达；某指标不完整时不计算该指标剩余额度 |
| 超出目标 | 摄入大于目标时明确展示超出量 |
| 纠正记录 | 补记、修改、删除立即反映在汇总中，跨日期移动同时更新两天 |
| 网页可用性 | 手机和电脑均能完成流程；字段错误清晰，失败保留输入，提交中不能重复点击，页面刷新可用 |
